# SECURITY & ANTI-SPAM SAFEGUARDS: ARCLANE ENGINE

## 1. Global Kill Switch (`EMERGENCY_STOP`)

The platform contains a zero-latency hardware kill switch.

### Triggering Emergency Stop:
- **Via Environment Variable**: Set `EMERGENCY_STOP=true` in `.env`
- **Via Web UI / Telegram**: Type `/emergency_stop` or click **🛑 Abort Active Task**

### Behaviors during Emergency Stop:
- All outbound WhatsApp browser dispatches are immediately terminated.
- All scheduled follow-up sequences are suspended.
- No Google Maps scraping or LLM tokens are consumed.
- State is safely persisted in `reports/.crm_state/` for post-incident inspection.

---

## 2. Deterministic Deduplication & Suppression

- **Canonical E.164 Normalization**: Eliminates duplicate phone formats (`098...`, `+91 98...`, `98...`).
- **60-Day Contact Cooldown**: Any lead contacted within the last 60 days is automatically flagged `ALREADY_CONTACTED` and skipped.
- **Permanent Suppression List**: Any prospect sending an opt-out message (`STOP`, `Unsubscribe`, `Nahi chahiye`, `Don't message`) is added to `reports/.crm_state/suppression_list.json` and blocked permanently across all campaigns.

---

## 3. Human Approval Gate (`HUMAN_APPROVAL_REQUIRED`)

- By default, `HUMAN_APPROVAL_REQUIRED=true`.
- First-contact sales pitches are never transmitted autonomously.
- Messages enter state `AWAITING_APPROVAL`.
- The human operator can **APPROVE**, **EDIT**, or **REJECT** every outbound copy.

---

## 4. Secret Redaction & Token Safety

- The audit logger (`AuditLogger`) automatically parses all event payloads and redacts API keys, tokens, and authorization cookies with `[REDACTED_SECRET]`.
- Frontend code generated by AI is scanned by `WebsiteQAValidator` before deployment. Any embedded API keys or tokens result in immediate build rejection (`QA_FAILED`).
